# Поведінка інтерфейсу

Інтерфейс українською мовою. Грошові значення показуються у гривнях, дати й час у локалі uk-UA. Статуси, оплати, призначення кур'єра й обмеження редагування адреси визначає SQL-схема та API, перевірені в `tests/checkout.test.mjs`, `tests/delivery-map.test.mjs` і `tests/browser-runtime.test.mjs`.

Поля мають спільні текстові помилки й зберігають введені значення. Надсилання блокує повторний клік. Критичні помилки залишаються в контексті операції. Пошук, фільтри та сторінки зберігаються в URL; зміна даних оновлює спільні ресурси.

## Два режими даних

У Pages кожен відвідувач керує лише своєю БД в IndexedDB. Публічної адміністративної БД немає. Діалог, кошик, оплати та історія використовують той самий браузерний API; параметризований SQL і транзакції зберігають зв'язність даних. Спільний банер завжди позначає демонстрацію. Справжні оплати й надсилання ресторанам відсутні.

Локальна версія використовує NestJS і PostgreSQL через той самий клієнтський контракт. Сервер перевіряє автентифікацію, роль та власника запису. За замовчуванням робочі API доступні лише адміністратору; винятки для каталогу й власних замовлень визначені явними декораторами та перевірками. Host, Origin та loopback додатково обмежують локальний доступ.

## Акаунти

`entities/session/provider.tsx` володіє станом входу, `pages/account` формами входу та реєстрації. Роль береться з `/auth/session`, а не з полів форми. `App.tsx` закриває прямі адміністративні URL для користувача та пропонує вхід гостю. Сервер і браузерний API незалежно перевіряють дозвіл на операцію.

Історія читається з `/orders/recent` для поточного власника. Зміна акаунта прибирає попередні ресурси та діалоги. Кошик зберігається; контакти й незавершене оформлення ізольовані за user id. Ключ нового оформлення включає user id; збережений ключ невизначеного запиту повторюється без зміни. Перевірки: `tests/auth.test.mjs`, `tests/browser-auth.test.mjs`, `tests/cart.test.mjs`.

Очищення даних сайту видаляє лише локальну демонстрацію. Початкові клієнти та кур'єри вигадані. Геолокація публікується тільки за явною дією користувача й дозволом браузера. Введені на карті координати передаються провайдерам пошуку адрес або маршруту лише для відповідної функції.


## Завантаження даних і зображень

Початковий `Async` має один доступний статус завантаження й неінтерактивний skeleton. Каталог і меню передають макет, що відповідає майбутній геометрії. Шари скелетона приховані від допоміжних технологій; жоден placeholder не потрапляє в порядок Tab. При фоновому оновленні зберігаються дані, фокус і чинні дії. Помилка має власний стан та повтор, порожній результат має завершений empty state.

`CatalogPhoto` окремо керує завантаженням файлу: `loading`, `ready`, `unavailable`. `onLoad` та перевірка вже кешованого зображення завершують shimmer; помилка показує наявний fallback без нескінченного loading. Відсутній hero-слот після отримання каталогу не рендериться. Поки початкові дані ще завантажуються, показані три skeleton-картки; кожне меню далі завершує своє очікування незалежно.

Єдині токени shimmer та руху належать `app/styles.css`; клас `.skeleton` спільний для всіх екранів. `prefers-reduced-motion` вимикає анімацію, а зміна акаунта й помилка доступу продовжують очищувати попередні дані через наявний контракт `Async` та сеансу. Перевірки: `tests/loading-ui.test.mjs`, `tests/home.test.mjs` і стани в браузері.


## Пошук страв

Головна й каталог використовують один пошук за назвою закладу, кухнею, назвою доступної страви або її категорією. Український регістр нормалізується однаково у PostgreSQL і Pages незалежно від системної locale; символи %, _ та зворотна риска сприймаються буквально. Недоступні страви не створюють збігів. Неактивний заклад зберігається у каталозі з явною позначкою.

Один результат відповідає одному закладу: поруч є кількість знайдених страв і до трьох прикладів з фото та ціною. Сортування прикладів за ціною, назвою й id стабільне. Карта використовує той самий пошук і рахує лише знайдені заклади. Порожній запит не підвантажує приклади страв.

Посилання на конкретну страву передає q для початкового фільтра меню та catalog_q для повернення до початкового запиту. Звичайні переходи очищують цей контекст. Форми, URL, пагінація, skeleton, помилка та повтор використовують наявних власників Search, PageLink, useResource й Async. Перевірки: tests/catalog-search-contract.mjs в обох runtime, tests/search-navigation.test.mjs, tests/loading-ui.test.mjs і браузер.


## Ціни та порівняння страв

Пошуковий запит за замовчуванням відкриває вигляд Страви. Окремі вигляди Заклади й Карта зберігають наявні контракти. Панель швидких запитів кухні в каталозі видима у виглядах закладів і карти; у вигляді страв працюють справжні фільтри бюджету й закладу. Сортування ціни виконується числовим SQL до пагінації, охоплює всі результати та має стабільний порядок за id. GET /menu відкритий для читання каталогу; POST і PATCH залишаються адміністративними. Повертаються тільки активні заклади й доступні страви.

Бюджет є включною верхньою межею ціни порції, значення 0 дозволене. Field володіє нативними input/select, форма має явне застосування й текстову помилку з фокусом у полі бюджету. Порожній результат пропонує скинути активні фільтри або пошуковий запит. useResource відкидає застарілі відповіді. Фільтри й до трьох обраних id зберігаються в URL. catalog_state переносить їх у меню й назад лише за білим списком; звичайні переходи прибирають цей контекст.

features/compare-dishes володіє вибором і порівнянням. Панель показує назви закладів поруч із назвами страв, дозволяє прибрати позицію та відкрити спільний Modal. Повторний GET /menu за ids отримує поточні дані каталогу незалежно від фільтрів. Недоступні позиції позначаються; помилка має повтор, під час оновлення відкриття порівняння заблоковане. Порівняння використовує семантичну таблицю максимум із трьома позиціями й окреме горизонтальне прокручування на вузькому екрані.

Збіг назви не встановлює тотожність рецепта або порції. Показуються оригінальна порція, склад, джерело та дата звіряння ціни. Вартість на 100 г/мл розраховується лише з одного явного значення г, кг, мл чи л. Складені порції, розміри в сантиметрах, штуки та текстові варіанти не перетворюються. Дані невідомої порції не вигадуються; доставка та додатки не включені у порівняння. Перевірки: спільний catalog-search-contract для PostgreSQL і Pages, price-comparison.test.mjs, loading-ui.test.mjs, search-navigation.test.mjs та браузер.
