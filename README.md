# Сусідня кухня

Інтерактивна демоверсія сервісу доставки їжі з київських закладів.

[Відкрити сайт](https://subvincdebian.github.io/susidnia-kukhnia/)

Каталог містить 10 закладів, 318 страв і фотографії з посиланнями на джерела. Можна зібрати кошик, оформити демонстраційне замовлення, вибрати адресу на карті, змінювати його стан, призначати кур'єра, листуватися та переглядати аналітику.

## Як працює демоверсія

GitHub Pages запускає React і PostgreSQL у браузері через PGlite. Дані зберігаються в IndexedDB цього браузера та залишаються після оновлення сторінки. Інші відвідувачі мають власну копію даних. Очищення даних сайту скидає демонстрацію.

Замовлення не надсилаються закладам. Оплати й повернення імітуються, банківські реквізити не запитуються. Для перевірки форм використовуй вигадані контакти. Проєкт не представляє перелічені ресторани.

## Вхід і ролі

Каталог доступний гостям. Для оформлення й перегляду власних замовлень потрібно увійти або створити акаунт. Користувач бачить лише свою історію; адміністратор додатково відкриває керування доставкою, каталогом, кур'єрами та аналітикою.

Для демонстрації створюються два публічні вигадані акаунти:

| Роль | Пошта | Пароль |
| --- | --- | --- |
| Адміністратор | `admin@demo.test` | `AdminDemo2026!` |
| Користувач | `user@demo.test` | `UserDemo2026!` |

У Pages вхід і ролі працюють у локальній БД відвідувача. Це демонстрація поведінки, а не захист спільної серверної бази від власника браузера. Оновлення зі старої версії зберігає наявні локальні записи.

Перше відкриття завантажує рушій БД, тому може тривати довше. Потрібен сучасний браузер із підтримкою WebAssembly, Web Workers та IndexedDB. Карти, пошук адрес і маршрути використовують OpenStreetMap, Photon та OSRM; їх доступність залежить від зовнішніх сервісів. Позиція кур'єра змінюється вручну або передається з дозволеної геолокації, автоматичний рух не імітується як GPS.

## Структура

- `apps/web` - React, TypeScript, Vite, FSD, Leaflet, браузерний API та PGlite.
- `apps/backend` - NestJS, Fastify, Prisma, PostgreSQL для локального запуску.
- `data` - каталог, координати, вигадані демонстраційні записи та джерела фотографій.
- `db` - SQL-схема й фікстури для перевірок.
- `scripts` - запуск, міграції, імпорт каталогу й збірка Pages.
- `tests` - перевірки кошика, замовлень, БД, карт та браузерного API.

## Перегляд збірки Pages локально

Потрібен Node.js 24.11 або новіший.

```sh
npm ci --workspaces --include-workspace-root
npm run build:pages
npm run preview:pages
```

Відкрити `http://127.0.0.1:4173/susidnia-kukhnia/`.

## Локальна серверна версія

На Windows x64 запуск автоматично готує локальний PostgreSQL і збирає застосунок:

```sh
npm ci --workspaces --include-workspace-root
npm start
```

Відкрити `http://127.0.0.1:3000`. Робочі дані зберігаються в `.local`, яку не слід публікувати. Для зупинки натиснути Ctrl+C. NestJS перевіряє роль і власника запису для кожного захищеного запиту. Паролі хешуються PBKDF2-SHA256; токени сеансів передаються в HttpOnly cookie, у БД зберігаються їхні хеші. Сервер слухає лише loopback. Публічне серверне розгортання потребує окремого хостингу й HTTPS; публічні демо-акаунти призначені для тестових даних.

## Перевірки

```sh
npm run check
npm test
```

Для окремої перевірки браузерних транзакцій: `npm run test:browser`.

## Публікація

Зміни в `main` запускають `.github/workflows/pages.yml`: перевірку фронтенду, тести браузерного API, збірку та розгортання GitHub Pages. Згенеровані SQL/JSON для браузера та `dist` не зберігаються в Git. Для іншого імені репозиторію workflow передає відповідний `DELIVERY_BASE_PATH`.

## Каталог і фотографії

Ціни є знімком каталогу на зазначену в інтерфейсі дату, а не поточними пропозиціями ресторанів. [Джерела](data/Джерела.md) також записані в даних каталогу. Назви, логотипи та фотографії належать відповідним власникам; цей репозиторій не надає ліцензії на їх комерційне використання.
