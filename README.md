# Сусідня кухня

Навчальний сайт для курсової роботи: інтерактивна демонстрація доставки їжі з київських закладів. Український інтерфейс поєднує каталог страв, кошик, замовлення, карти та робочий простір адміністратора.

[Відкрити демоверсію](https://subvincdebian.github.io/susidnia-kukhnia/) · [Frontend](apps/web/src/) · [Backend](apps/backend/) · [Візуальна система](DESIGN.md)

## Можливості

- Каталог 10 закладів і 318 страв із фотографіями та посиланнями на джерела.
- Кошик, демонстраційне замовлення, історія користувача й вибір адреси на карті.
- Керування станами доставки, кур'єрами й каталогом, листування та аналітика.
- Окремі сценарії гостя, користувача й адміністратора.

**Стек:** React, TypeScript, Vite, Leaflet і PGlite у frontend; NestJS, Fastify, Prisma та PostgreSQL у локальній серверній версії. npm workspaces; код frontend організовано за Feature-Sliced Design.

## Межі навчальної демонстрації

Замовлення не надсилаються закладам. Оплати й повернення імітуються, банківські реквізити не запитуються. Для перевірки форм використовуй вигадані контакти. Проєкт не представляє перелічені ресторани.

У GitHub Pages React і PostgreSQL через PGlite працюють у браузері. Дані зберігаються в IndexedDB та залишаються після оновлення сторінки; кожен відвідувач має власну копію. Очищення даних сайту скидає демонстрацію. Вхід і ролі в цій версії демонструють поведінку інтерфейсу, а не захищають спільну серверну БД від власника браузера.

## Запуск

Потрібні **Node.js 24.11+** та npm. Команди виконуються з кореня репозиторію.

```sh
npm ci --workspaces --include-workspace-root
npm run build:pages
npm run preview:pages
```

Відкрити `http://127.0.0.1:4173/susidnia-kukhnia/`.

Для локальної серверної версії на **Windows x64** після встановлення залежностей:

```sh
npm start
```

Скрипт готує локальний PostgreSQL і збирає застосунок. Адреса: `http://127.0.0.1:3000`; робочі дані зберігаються в `.local`, яку не слід публікувати. Зупинка — Ctrl+C.

| ---------------------- | ----------------------------------------------------- |
| `npm run check`        | Prisma, TypeScript та перевірки структури проєкту     |
| `npm test`             | Серверні, браузерні та предметні перевірки з `tests/` |
| `npm run test:browser` | Транзакції та автентифікація браузерного API          |

Це доступні команди проєкту; їх наявність не означає, що всі інтеграції перевірено в кожному середовищі.

Для перевірки створюються два публічні вигадані акаунти:

| Роль          | Пошта             | Пароль           |
| ------------- | ----------------- | ---------------- |
| Адміністратор | `admin@demo.test` | `AdminDemo2026!` |

Користувач переглядає власну історію; адміністратор додатково відкриває керування доставкою, каталогом, кур'єрами й аналітикою. Каталог доступний гостям.

Перше відкриття Pages завантажує рушій БД, тому може тривати довше. Потрібен браузер із WebAssembly, Web Workers та IndexedDB. Карти, пошук адрес і маршрути використовують OpenStreetMap, Photon та OSRM, доступність яких залежить від зовнішніх сервісів. Позиція кур'єра змінюється вручну або передається з дозволеної геолокації; автоматичний рух не видається за GPS.

Локальний NestJS сервер перевіряє роль і власника захищених записів. Паролі хешуються PBKDF2-SHA256; токени сеансів передаються в HttpOnly cookie, у БД зберігаються їхні хеші. Сервер слухає лише loopback. Публічне серверне розгортання потребує окремого хостингу й HTTPS; демо-акаунти призначені для тестових даних.

Зміни в `main` запускають [workflow Pages](.github/workflows/pages.yml): перевірку frontend, тести браузерного API, збірку та розгортання. Згенеровані SQL/JSON для браузера та `dist` не зберігаються в Git. Для іншого імені репозиторію workflow передає відповідний `DELIVERY_BASE_PATH`.

## Каталог і права на матеріали

Ціни є знімком каталогу на зазначену в інтерфейсі дату, а не поточними пропозиціями ресторанів. [Джерела](data/Джерела.md) також записані в даних каталогу. Назви, логотипи та фотографії належать відповідним власникам; цей репозиторій не надає ліцензії на їх комерційне використання.
